Ranks outdoor and indoor activities for the next 7 days of a city's weather forecast.

Spec-first contract written by the test suite before any implementation exists. Every assumption made here is listed in the README under "Assumptions to confirm".

Weather data is sourced from Open-Meteo (geocoding, forecast and marine APIs). The service must read the Open-Meteo base URLs from configuration so that the test suite can point it at a stub server:

  • OPEN_METEO_GEOCODING_URL (default https://geocoding-api.open-meteo.com)
  • OPEN_METEO_FORECAST_URL (default https://api.open-meteo.com)
  • OPEN_METEO_MARINE_URL (default https://marine-api.open-meteo.com)

Locations

Find a city or town from a full or partial name.

Search cities and towns by full or partial name (autocomplete).

Prefix matching is case-insensitive and diacritic-insensitive ("zur" matches "Zürich"). A query of exactly 2 characters only returns exact name matches (mirrors Open-Meteo). No match is not an error: the response is 200 with an empty matches list so the front end can render "No places found" without error handling.

query Parameters
query
required
string [ 2 .. 100 ] characters
Examples:
  • query=Cham -
  • query=Zürich -

Full or partial city/town name. Leading and trailing whitespace is ignored.

limit
integer [ 1 .. 20 ]
Default: 10

Maximum number of matches to return.

Activity rankings

Daily activity rankings driven by the weather forecast.

Rank Skiing, Surfing, Outdoor Sightseeing and Indoor Sightseeing for each of the next 7 days.

Provide exactly one of city or locationId.

  • city resolves to the most relevant place whose name matches exactly (case- and diacritic-insensitive), as ordered by Open-Meteo (largest population first). Most names exist in several countries (Paris FR / Paris US-TX), so the response lists the other same-named places in alternativeMatches and the front end can offer "Not this Paris?" followed by a call with locationId.
  • When no place matches the name exactly, the API responds 404 with prefix-matched suggestions so the front end can offer "Did you mean Chamonix?".
  • locationId is the id returned by /v1/locations and is never ambiguous.

Within each day the four activities are ordered by rank (1 = most suitable).

query Parameters
city
string [ 2 .. 100 ] characters

Full city or town name. Mutually exclusive with locationId.

locationId
integer >= 1

Location identifier from /v1/locations. Mutually exclusive with city.

Responses

Local service (configurable through API_BASE_URL in the test suite)

http://localhost:3000/v1/activity-rankings
